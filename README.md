# Orbit AI

一個以瀏覽器為基礎、免安裝、免登入的智慧課表與校園時間管理工具。

**🚀 [立即使用 Orbit AI](https://jaypengx-collab.github.io/Orbit/)**

Orbit AI 將個人課表轉換成即時資訊面板：打開網頁就能立刻看到「現在上什麼課、還剩多久、在哪裡上、下一堂是什麼」，並提供課表編輯、外觀客製化、事件倒數、AI 課表圖片辨識、資料備份與還原等完整功能。

> 本文件同時作為：**① 使用者操作手冊**、**② 專案書面說明（供課堂 / 專題審閱）**、**③ AI 協作開發指南（給 AI 輔助編碼 / vibe coding 時閱讀）**。內容盡量完整，讀者可依需求跳到對應章節閱讀。

## 專案動機與目標

在學校裡，課表資訊常常分散在紙本課表、Excel 表格或校務系統的多層選單中，想知道「現在這堂是什麼課」「還剩幾分鐘」都要多點幾次才找得到。Orbit AI 的出發點，是把「查課表」這個高頻率、低資訊密度的動作，簡化成「打開網頁就直接看到答案」。

這是一個**個人獨立開發的自主專案（self project）**，從需求發想、介面設計、前端邏輯、資料儲存、到 AI 影像辨識整合，皆由作者獨力完成，沒有使用任何前端框架或建置工具，目的之一也是刻意練習「用原生 HTML / CSS / JavaScript 就把一個具備真實可用性的產品做出來」。

專案希望達成的目標大致有三個層面：

* **實用面**：解決自己與同學每天都會遇到的小問題——快速掌握目前課程、剩餘時間、下一堂課地點與教師。
* **技術面**：練習純前端狀態管理（不依賴框架）、瀏覽器端資料持久化（`localStorage`）、時間 / 週次 / 星期的邏輯運算、資料版本相容與遷移、以及呼叫外部 AI API（Gemini）做影像辨識並將非結構化結果轉換成可驗證的結構化資料。
* **工程面**：在沒有打包工具的前提下，仍嘗試維持「可維護」的程式碼組織方式（單一邏輯檔案內以區塊註解分段、統一的資料正規化流程、匯入前預覽與驗證機制），並持續優化載入效能與程式碼精簡度（見下方〈專案現況與後續方向〉的實際 commit 紀錄）。

## 功能特色

### 📅 即時課表

Orbit AI 會根據目前時間自動判斷課表狀態。

主畫面可以顯示：

* 目前課程
* 授課教師
* 上課教室
* 目前課程剩餘時間
* 下一堂課
* 下一堂課的教師與教室
* 當日課表
* 目前週次

系統會隨著時間自動更新課程狀態，一天的課程結束後也會自動切換至下一個上課日。

---

### 🗓️ 每週課表

支援以星期為單位管理課表，可以設定：

* 星期一至星期日的課程
* 每節課的順序
* 不同週次（單週 / 雙週）的課程安排
* 上課時間、下課時間

使用者可以直接在課表編輯器中修改課程安排。

---

### 🔔 自訂鐘聲時間

可以自行設定每一節課的開始與結束時間。例如：

```text
第一節  08:10 - 09:00
第二節  09:10 - 10:00
第三節  10:10 - 11:00
```

系統會根據這些時間判斷目前課程與下一堂課，時間資料也會經過驗證，避免出現無效時間或課程時間互相重疊的情況。

---

### ☕ 特殊時段

除了正常課程之外，也可以設定特殊時段，例如：

* 午休
* 打掃
* 其他非上課時間

在特殊時段內，主畫面會顯示對應名稱與倒數計時，而不是一般課程資訊。

---

### 👨‍🏫 教師與課程資料庫

每個課程可以包含：

* 課程名稱
* 授課教師
* 教室
* 課程識別名稱

教師與課程資料可以透過編輯器修改與重新排序。

---

### 🎯 事件倒數

Orbit AI 支援自訂重要事件倒數，每個事件可以設定：

* 事件名稱
* 日期
* 顯示順序

例如：學測、期中考、期末考、校慶。主畫面可以顯示即將到來的事件以及剩餘時間。

---

### 🎨 外觀自訂

內建完整的外觀設定系統，支援：

* 淺色模式 / 深色模式
* 自訂主要顏色、次要顏色
* 預設配色
* 自訂樣式儲存槽
* 套用前預覽

外觀設定與課表資料分開管理，因此修改配色不會影響課表內容。

---

### 🧪 時間模擬

內建測試模式，可以手動指定星期與時間，藉此模擬特定時間下的課表狀態。例如可以測試：

* 第一節課開始前
* 上課中
* 下課後
* 午休期間
* 下一堂課
* 當日課程結束

這對開發與測試課表邏輯特別有用（也是本專案在沒有自動化測試框架的情況下，用來手動驗證核心邏輯的主要方式）。

---

### 📷 AI 課表辨識

Orbit AI 可以透過 Gemini AI 從課表圖片中自動辨識課程資料。基本流程：

```text
選擇課表圖片
      ↓
載入圖片
      ↓
Gemini AI 分析
      ↓
辨識課程資料
      ↓
驗證資料
      ↓
顯示辨識結果
      ↓
使用者確認 / 修改
      ↓
匯入課表
```

AI 可以嘗試辨識：課程、教師、教室、每節課時間、星期安排、特殊時段、不同週次安排、課表上的重要日期。

AI 辨識結果**不會直接覆蓋**原本的課表，而是會先提供預覽與確認，讓使用者檢查資料後再匯入。

## 快速開始

### 系統需求

正常使用課表功能只需要：

* 現代瀏覽器（Google Chrome、Microsoft Edge、Safari、Firefox 等）
* 完整的專案資料夾（`index.html`、`css/`、`js/`）

不需要安裝 Node.js，也不需要執行任何建置工具（no build step）。

### 方式一：線上使用（推薦）

不需要下載任何檔案，直接開啟：

**https://jaypengx-collab.github.io/Orbit/**

即可使用 Orbit AI。網站由 GitHub Pages 託管，`main` 分支有更新時會自動重新部署（見 `.github/workflows/static.yml`）。

### 方式二：本機執行

1. 下載或 clone 整個專案資料夾：
   ```bash
   git clone https://github.com/jaypengx-collab/Orbit.git
   ```
2. 用瀏覽器直接開啟資料夾內的 `index.html`，或啟動一個簡單的本機伺服器（建議，某些瀏覽器對 `file://` 協定的本機儲存 / fetch 行為較保守）：
   ```bash
   cd Orbit
   python -m http.server 8843
   # 開啟 http://localhost:8843/
   ```
3. Windows 使用者可直接雙擊執行專案內附的 `run-local.bat`，會自動用 Python 內建的 `http.server` 在連接埠 `8843` 啟動並開啟瀏覽器。

`css/` 與 `js/` 目錄必須與 `index.html` 放在同一層，才能正確載入樣式與程式邏輯。

## 基本使用流程

### 1. 設定課表

點選右上角工具選單中的「編輯課表」，設定：

* 課程、教師、教室
* 每節課時間（鐘聲時間）
* 每週課表（含單 / 雙週差異）
* 特殊時段
* 倒數事件

完成後儲存，資料會寫入瀏覽器的 `localStorage`。

### 2. 查看主畫面

主畫面會根據目前時間自動計算：

```text
目前時間 → 星期 → 週次 → 今日課表 → 目前課程 → 下一堂課
```

使用者不需要手動切換目前課程，系統每秒鐘會重新計算一次狀態。

### 3. 使用時間模擬

如果需要測試課表在某個特定時間點的顯示狀態，可以開啟「時間模擬」面板，指定任意星期與時間，不需要真的等到那個時間。

### 4. 自訂外觀

進入「樣式工具」面板，可以選擇預設配色，或自行調整主要 / 次要顏色並儲存為自訂樣式槽，方便之後切換。

### 5.（選用）用 AI 辨識課表圖片

在編輯器中選擇「AI 辨識」，上傳課表照片或截圖，填入自己的 Gemini API Key 後即可自動辨識課程資料，確認無誤後再匯入。

## 技術棧與專案架構

### 技術棧

| 分類 | 使用技術 |
| --- | --- |
| 前端結構 | 純 HTML5（單一 `index.html`，無樣板引擎） |
| 樣式 | 純 CSS3（`css/styles.css`，CSS 變數 + 淺 / 深色主題 + 響應式設計） |
| 邏輯 | 原生 JavaScript（ES6+，`js/app.js`，無框架、無打包工具、無 TypeScript） |
| 資料持久化 | 瀏覽器 `localStorage`（`classFocusData` 鍵） |
| AI 辨識 | Google Gemini API（`generativelanguage.googleapis.com`），前端直接呼叫 |
| 部署 | GitHub Pages（`.github/workflows/static.yml` 自動部署） |
| 建置工具 | 無（No build step / no bundler / no package manager） |

刻意不使用框架與建置工具，是為了讓專案可以「複製整個資料夾就能跑」，也是本專案想練習的重點之一：在最少依賴的情況下組織一個中大型前端專案的程式碼。

### 專案架構

```text
index.html          — 版面標記（主畫面、課表編輯器、時間模擬面板、外觀設定面板等區塊）

css/
└── styles.css       — 全部樣式（淺色 / 深色模式、響應式設計、編輯器介面、外觀系統、動畫）

js/
└── app.js           — 所有邏輯，依功能分段（每段開頭有 `// ---- 原檔名 ----` 註解方便定位）

.github/
└── workflows/
    └── static.yml   — GitHub Pages 自動部署設定

run-local.bat        — Windows 一鍵啟動本機伺服器的批次檔
```

`js/app.js`（約 4,500 行）內部依原本的模組拆分順序，用區塊註解串接，實際對照如下：

| 區塊註解 | 內容 |
| --- | --- |
| `js/data.js` | 資料正規化、驗證、`localStorage` 讀寫、預設資料 |
| `js/schedule.js` | 建立執行中課表、星期 / 週次計算 |
| `js/appearance.js` | 外觀（主題色、深淺色模式）系統 |
| `js/dashboard.js` | 主畫面即時更新核心（`update()`）、倒數計時 |
| `js/editor-backup.js` | 備份匯出 / 匯入、v2 傳輸格式編碼 |
| `js/editor-core.js` | 課表編輯器主流程 |
| `js/editor-teachers.js` | 教師 / 課程資料編輯 |
| `js/editor-schedule.js` | 每週課表編輯（排課） |
| `js/dashboard-render.js` | 主畫面 DOM 渲染 |
| `js/gemini-ocr.js` | Gemini AI 課表圖片辨識 |
| `js/bootstrap.js` | 啟動流程：讀取設定、建立課表、啟動每秒更新的時鐘 |
| `js/testsim-runtime.js` | 時間模擬狀態機 |

`index.html` 只載入 `css/styles.css` 與 `js/app.js` 這兩個檔案。專案早期依功能拆成十幾個 `<script>`，每次載入都要多發十幾個 HTTP 請求，啟動時還會用同步請求重新下載每個檔案來計算版本號，導致首次載入明顯卡頓；合併成單一檔案並把版本號計算改成非同步後，大幅縮短了啟動時間（實際修正見 commit `07b5294 Fix real root cause of slow loading: blocking synchronous version-hash fetch`）。

`js/app.js` 內所有區塊共用同一個全域作用域（沒有打包工具，也沒有模組系統），因此**檔案內的先後順序有意義**：後面的區段可以使用前面區段定義的函式與變數。`bootstrap.js` 區段必須排在其他功能模組之後、`testsim-runtime.js` 之前執行。

## 資料儲存與資料結構

### 儲存方式

Orbit AI 使用瀏覽器的 `localStorage` 儲存課表資料（鍵名 `classFocusData`）。因此一般使用時：

* 不需要資料庫
* 不需要登入
* 不需要後端伺服器
* 關閉網頁後資料仍可保留（除非清除瀏覽器資料）

儲存內容包括：課表、教師資料、教室資料、上下課時間、特殊時段、倒數事件、週次設定、外觀設定、Gemini API Key。

程式具有資料版本管理機制（`ORBIT_APP_ID` / `ORBIT_STORAGE_SCHEMA`），可以偵測目前儲存資料是否符合程式目前使用的資料格式，避免舊版資料造成錯誤。

### 主要資料結構

#### `teacherDB`

儲存課程、教師與教室資訊，概念上為：

```text
課程名稱 → [課程名稱, 教師, 教室]
```

#### `locationDB`

儲存課程與教室的對應關係。

#### `weeklySchedule`

儲存每一天的課程安排，星期使用 JavaScript 的 `Date.getDay()` 編號：

```text
0 = 星期日   1 = 星期一   2 = 星期二   3 = 星期三
4 = 星期四   5 = 星期五   6 = 星期六
```

#### `bellTimes`

儲存每一節課的開始與結束時間：

```json
[
  ["08:10", "09:00"],
  ["09:10", "10:00"]
]
```

#### `breakTimes`

儲存特殊時段：

```json
[
  {
    "name": "午休",
    "start": "12:00",
    "end": "13:00"
  }
]
```

#### `countdownEvents`

儲存事件倒數資料：

```json
[
  {
    "name": "期末考",
    "date": "2027-01-22"
  }
]
```

程式會在載入與修改資料時，透過 `data.js` 區段內的正規化 / 驗證函式（如 `normalizeCountdownEvents`、`validateTimeIntervals`、`sanitizeBreakTimes` 等）進行資料正規化與驗證，避免無效或衝突的資料進入系統。

## 資料備份與匯入

Orbit AI 提供完整的課表設定備份與轉移功能，可以：

* 匯出設定
* 複製備份內容
* 在其他裝置貼上
* 匯入設定
* 合併不同設定
* 預覽匯入後的變更

匯出的資料使用壓縮與 Base64 編碼（v2 傳輸格式），以減少備份文字的大小；系統同時支援目前的壓縮格式，以及舊版的未壓縮 JSON 備份格式（v1 解碼器已於後續版本移除，目前僅支援 v2）。

在正式套用匯入資料前，系統會顯示變更內容（diff 預覽），避免使用者不小心覆蓋原有課表。

## 即時狀態計算邏輯

Orbit AI 的核心 `update()` 函式（定義於 `js/app.js` 內 `js/dashboard.js` 區段）會持續重新計算目前狀態，主要流程包括：

```text
取得目前時間
    ↓
判斷星期
    ↓
判斷週次
    ↓
取得今日課表
    ↓
判斷目前課程
    ↓
判斷下一堂課
    ↓
判斷是否為特殊時段
    ↓
更新倒數計時
    ↓
更新畫面
```

`bootstrap.js` 區段會在啟動時建立一個每秒執行一次的計時器來呼叫 `update()`，因此主畫面的資訊會隨著時間自動變化，不需要重新整理頁面。

## Gemini AI 課表辨識

AI 課表辨識功能需要使用者提供自己的 **Gemini API Key**。

* API Key 會儲存在瀏覽器的本機儲存空間中（鍵名 `orbitAiGeminiApiKey`），而不是直接寫死在程式碼裡。
* 使用 AI 辨識課表時，選擇的課表圖片會直接從瀏覽器呼叫 Gemini API（`generativelanguage.googleapis.com`）進行分析，過程中沒有經過任何自建後端伺服器轉送。
* AI 辨識功能屬於**選用功能**，不影響一般課表功能（手動編輯課表）的使用。

> **請不要將自己的 API Key 直接寫進 `index.html` 或 `js/app.js` 並公開分享／提交／推送到公開 repository。**

## 隱私與安全

### 課表資料

一般課表資料儲存在使用者自己的瀏覽器 `localStorage` 中，不會上傳到任何伺服器。

### AI 課表辨識

使用 Gemini AI 時，所選擇的課表圖片會傳送至 Google 的 Gemini API。因此請避免上傳包含不希望傳送至外部 AI 服務之敏感資訊的圖片。

### API Key

Gemini API Key 不應直接寫入原始碼；專案目前將使用者提供的 Key 儲存在瀏覽器本機儲存空間中，且只在使用者主動觸發 AI 辨識時才會被用來呼叫外部 API。

## 響應式設計

Orbit AI 支援桌面與行動裝置，包含：

## 設計理念

Orbit AI 主要建立在三個核心概念上。

### 1. 一眼就能看懂

使用者打開頁面後，最重要的資訊應該立即可見：

> **我現在要上什麼？**
> **還剩多久？**
> **在哪裡上？**
> **下一堂是什麼？**

### 2. 安全地修改課表

課表是每天都會使用的重要資料，因此修改設定時需要避免意外覆蓋，系統因此提供：

* 修改狀態偵測
* 儲存前確認
* 匯入預覽
* 資料驗證
* 備份與還原

### 3. 簡單且容易攜帶

整個應用程式只由靜態的 HTML、CSS、JavaScript 檔案組成，不需要建置流程，因此可以很容易地複製、分享、備份、本機執行、放到任何靜態網站主機、在不同裝置之間轉移。

## 開發指南（給人類開發者）

Orbit AI 的程式碼依功能拆分於 `css/` 與 `js/` 目錄（詳見〈技術棧與專案架構〉）。

**修改樣式**請編輯 `css/styles.css`。CSS 變數集中定義主題色與間距，深 / 淺色模式各自覆寫對應變數。

**修改邏輯**請編輯 `js/app.js`，依 `// ---- 原檔名 ----` 註解找到對應區段（例如課表計算在「schedule.js」段、編輯器在「editor-*.js」段、AI 辨識在「gemini-ocr.js」段）。新增程式碼時：

* 請留在對應區段內，並注意檔案內的先後順序（後面的區段可以使用前面區段定義的函式與變數，反之不行）。
* **不要**另外新增 `<script>` 標籤，避免又拆回多檔案而讓載入變慢（見〈技術棧與專案架構〉中提到的效能修正）。
* 沒有 linter / formatter / 自動化測試框架，變更後請至少用「時間模擬」面板手動驗證核心邏輯（第一節課開始前 / 上課中 / 下課後 / 午休期間 / 下一堂課 / 當日課程結束等情境）。

整體資料流程可以理解為：

```text
使用者設定 → 資料正規化 → 儲存至 localStorage → 建立執行中的課表
    → 根據目前時間計算狀態 → 更新 UI
```

其中課表編輯器主要負責修改**設定資料**，而執行中的課表則負責提供主畫面即時運作所需的**衍生資料**。

## AI 協作開發指南（給 AI / vibe coding）

如果你是被要求協助修改此專案的 AI 助理，以下是快速上手所需的關鍵事實：

1. **這是零依賴的純靜態專案**：沒有 `package.json`、沒有 npm、沒有打包工具、沒有框架。所有 JavaScript 都在單一檔案 `js/app.js` 裡，所有 CSS 都在單一檔案 `css/styles.css` 裡。**不要**引入 npm、React、Vue、Webpack、Vite 等任何建置工具或框架，也不要把 `js/app.js` 重新拆回多個 `<script>` 檔案——這兩件事都違背本專案刻意選擇的「免建置、複製資料夾即可執行」架構。
2. **`js/app.js` 內部沒有模組系統**：所有函式與變數共享同一個全域作用域，靠檔案內「原檔名區塊」的先後順序保證依賴關係成立（見〈技術棧與專案架構〉表格）。新增功能時，把程式碼加在語意最相符的既有區段內；如果真的需要新區段，加在依賴它的程式碼之前、被依賴的程式碼之後。
3. **核心入口點**：
   * `loadData()` / `saveData()`（`data.js` 區段）：讀寫 `localStorage`（鍵 `classFocusData`）。
   * `buildSchedule()`（`schedule.js` 區段）：把設定資料轉成可查詢的「執行中課表」。
   * `update()`（`dashboard.js` 區段）：每秒執行一次的核心狀態機，決定主畫面顯示什麼。
   * `bootstrap.js` 區段：啟動流程，串起上面三者並啟動計時器。
4. **資料一律要正規化與驗證**：新增或修改任何會寫入 `localStorage` 的資料結構時，請比照現有的 `normalizeXxx()` / `validateXxx()` / `sanitizeXxx()` 函式風格（`data.js` 區段），先驗證再儲存，並考慮舊版資料的相容性（`ORBIT_STORAGE_SCHEMA`）。
5. **沒有自動化測試**：驗證邏輯是否正確的主要手段是〈時間模擬〉功能（`testsim-runtime.js` 區段）——可以手動指定星期與時間來檢查 `update()` 的輸出是否符合預期。修改課表計算 / 倒數邏輯後，務必用這個面板測過幾個邊界情境（節與節交界、午休前後、當日最後一節下課後等）。
6. **外部 API 只有一個**：Gemini API（`gemini-ocr.js` 區段），直接從前端呼叫，Key 存在 `localStorage`（`orbitAiGeminiApiKey`）。不要把任何 API Key 寫死進原始碼或提交進版本控制。
7. **修改樣式時**優先使用既有 CSS 變數（主題色、間距等），並同時檢查淺色 / 深色模式下的顯示效果，以及手機寬度下的版面（專案高度重視響應式設計，見〈響應式設計〉）。
8. **提交風格**：觀察既有的 git 歷史，commit message 偏好簡潔、祈使句、描述「做了什麼 / 修了什麼」，例如 `Fix real root cause of slow loading: blocking synchronous version-hash fetch`、`Remove dead code: unreferenced CSS selectors and no-op class churn`。請沿用相同風格，並優先做「刪減 / 簡化」而非「疊加抽象層」——本專案的近期開發歷史有明顯朝向精簡程式碼（移除死碼、合併重複規則、縮短備份格式）的趨勢。
9. **完成修改後的自我檢查清單**：
   * 是否仍然只有 `index.html` + `css/styles.css` + `js/app.js` 三個核心檔案（沒有新增建置產物）？
   * 新程式碼是否放在正確的區塊註解內，且沒有引用「後面才定義」的函式？
   * 涉及 `localStorage` 資料的變更是否經過正規化 / 驗證，且不會讓舊資料讀取失敗？
   * 是否用時間模擬面板實際驗證過行為？
   * 深色模式與手機版面是否正常？

## 常見問題 FAQ

**Q：需要註冊帳號或安裝 App 嗎？**
不需要。開啟網頁即可使用，資料存在你自己的瀏覽器裡。

**Q：換一台電腦或手機，課表資料會不見嗎？**
會。`localStorage` 是綁定瀏覽器 / 裝置的，換裝置前請先用〈資料備份與匯入〉功能匯出設定，再到新裝置匯入。

**Q：清除瀏覽器快取或紀錄，課表會不見嗎？**
如果清除的是「網站資料 / Cookie 與網站資料」，可能會連 `localStorage` 一起清掉，建議定期備份。

**Q：一定要用 AI 辨識功能嗎？**
不一定。AI 課表辨識是加分的輸入方式之一，完全可以只用手動編輯器建立課表，也不需要任何 API Key。

**Q：Gemini API Key 要去哪裡申請？會不會被本專案蒐集？**
Key 由使用者自行於 Google AI 平台申請，只會存在自己瀏覽器的本機儲存空間，並直接從瀏覽器呼叫 Gemini API，本專案（含其 GitHub Pages 靜態網站）不會蒐集或轉送這組 Key。

**Q：可以離線使用嗎？**
基本課表顯示 / 編輯 / 備份匯出入功能不需要網路即可運作（本機開啟即可）；但 AI 課表辨識功能需要網路連線才能呼叫 Gemini API。

## 已知限制

* 開啟 `index.html` 時，`css/` 與 `js/` 目錄必須存在於同一層，否則樣式與功能無法載入。
* 課表資料預設儲存在瀏覽器中，屬於單機 / 單瀏覽器儲存，沒有雲端同步。
* 清除瀏覽器網站資料可能會導致課表遺失，建議定期使用備份功能保存課表。
* AI 課表辨識並非百分之百準確，匯入前應確認辨識結果。
* Gemini AI 功能需要 API Key 與網路連線，AI 辨識效果也會受到課表圖片清晰度與格式影響。
* 專案目前沒有後端資料庫，也沒有多裝置即時同步機制。
* 專案目前沒有自動化測試套件，程式正確性主要仰賴手動測試與時間模擬功能。

Orbit AI 是一套以瀏覽器為基礎的智慧課表系統，目前整合了：

* 即時課表、每週課表

* 探索選用性的雲端同步方案（在不強迫使用者登入的前提下）
* 持續擴充 AI 辨識對不同課表版型的相容性
