# Orbit AI

一個以瀏覽器為基礎的智慧課表與校園時間管理工具。

**🚀 [立即使用 Orbit AI](https://jaypengx-collab.github.io/Orbit/)**

Orbit AI 將個人課表轉換成即時資訊面板，能顯示目前課程、剩餘時間、下一堂課、教室、教師、每週課表以及重要事件倒數。

本專案採用**純靜態多檔案架構**：`index.html` 只放版面標記，樣式集中於 `css/styles.css`，邏輯依功能拆成 `js/` 目錄下多個檔案，彼此以 `<script src>` 依序載入。不需要任何建置工具、打包器或後端伺服器，瀏覽器可直接讀取整個資料夾使用。

---

## 功能特色

### 📅 即時課表

Orbit AI 會根據目前時間自動判斷課表狀態。

主畫面可以顯示：

* 目前課程
* 授課教師
* 上課教室
* 目前課程剩餘時間
* 下一堂課
* 下一堂課的教師與教室
* 當日課表
* 目前週次

系統會隨著時間自動更新課程狀態。

當一天的課程結束後，也會自動切換至下一個上課日。

---

### 🗓️ 每週課表

支援以星期為單位管理課表。

可以設定：

* 星期一至星期日的課程
* 每節課的順序
* 不同週次的課程安排
* 上課時間
* 下課時間

使用者可以直接在課表編輯器中修改課程安排。

---

### 🔔 自訂鐘聲時間

可以自行設定每一節課的開始與結束時間。

例如：

```text
第一節  08:10 - 09:00
第二節  09:10 - 10:00
第三節  10:10 - 11:00
```

系統會根據這些時間判斷目前課程與下一堂課。

時間資料也會經過驗證，避免出現無效時間或課程時間互相重疊的情況。

---

### ☕ 特殊時段

除了正常課程之外，也可以設定特殊時段，例如：

* 午休
* 打掃
* 其他非上課時間

在特殊時段內，主畫面會顯示對應名稱與倒數計時，而不是一般課程資訊。

---

### 👨‍🏫 教師與課程資料庫

每個課程可以包含：

* 課程名稱
* 授課教師
* 教室
* 課程識別名稱

教師與課程資料可以透過編輯器修改與重新排序。

---

### 🎯 事件倒數

Orbit AI 支援自訂重要事件倒數。

每個事件可以設定：

* 事件名稱
* 日期
* 顯示順序

例如：

```text
學測
期中考
期末考
校慶
```

主畫面可以顯示即將到來的事件以及剩餘時間。

---

### 🎨 外觀自訂

內建完整的外觀設定系統。

支援：

* 淺色模式
* 深色模式
* 自訂主要顏色
* 自訂次要顏色
* 預設配色
* 自訂樣式儲存槽
* 套用前預覽

外觀設定與課表資料分開管理，因此修改配色不會影響課表內容。

---

### 🧪 時間模擬

內建測試模式，可以手動指定：

* 星期
* 時間

藉此模擬特定時間下的課表狀態。

例如可以測試：

* 第一節課開始前
* 上課中
* 下課後
* 午休期間
* 下一堂課
* 當日課程結束

這對開發與測試課表邏輯特別有用。

---

### 📷 AI 課表辨識

Orbit AI 可以透過 Gemini AI 從課表圖片中自動辨識課程資料。

基本流程：

```text
選擇課表圖片
      ↓
載入圖片
      ↓
Gemini AI 分析
      ↓
辨識課程資料
      ↓
驗證資料
      ↓
顯示辨識結果
      ↓
使用者確認 / 修改
      ↓
匯入課表
```

AI 可以嘗試辨識：

* 課程
* 教師
* 教室
* 每節課時間
* 星期安排
* 特殊時段
* 不同週次安排
* 課表上的重要日期

AI 辨識結果不會直接覆蓋原本的課表，而是會先提供預覽與確認，讓使用者檢查資料後再匯入。

## 💾 資料儲存

Orbit AI 使用瀏覽器的 `localStorage` 儲存課表資料。

因此一般使用時：

* 不需要資料庫
* 不需要登入
* 不需要後端伺服器
* 關閉網頁後資料仍可保留

儲存內容包括：

* 課表
* 教師資料
* 教室資料
* 上下課時間
* 特殊時段
* 倒數事件
* 週次設定
* 外觀設定
* Gemini API Key

程式也具有資料版本管理機制，可以偵測目前儲存資料是否符合程式使用的資料格式。

## 📦 資料備份與匯入

Orbit AI 提供完整的課表設定備份與轉移功能。

可以：

* 匯出設定
* 複製備份內容
* 在其他裝置貼上
* 匯入設定
* 合併不同設定
* 預覽匯入後的變更

匯出的資料會使用壓縮與 Base64 編碼，以減少備份文字的大小。

系統同時支援目前的壓縮格式，以及舊版的未壓縮 JSON 備份。

在正式套用匯入資料前，系統也會顯示變更內容，避免使用者不小心覆蓋原有課表。

## 🗂️ 資料結構

### `teacherDB`

儲存課程、教師與教室資訊。

概念上為：

```text
課程名稱 → [課程名稱, 教師, 教室]
```

### `locationDB`

儲存課程與教室的對應關係。

### `weeklySchedule`

儲存每一天的課程安排。

星期使用 JavaScript 的 `Date.getDay()` 編號：

```text
0 = 星期日
1 = 星期一
2 = 星期二
3 = 星期三
4 = 星期四
5 = 星期五
6 = 星期六
```

### `bellTimes`

儲存每一節課的開始與結束時間。

例如：

```json
[
  ["08:10", "09:00"],
  ["09:10", "10:00"]
]
```

### `breakTimes`

儲存特殊時段。

例如：

```json
[
  {
    "name": "午休",
    "start": "12:00",
    "end": "13:00"
  }
]
```

### `countdownEvents`

儲存事件倒數資料。

例如：

```json
[
  {
    "name": "期末考",
    "date": "2027-01-22"
  }
]
```

程式會在載入與修改資料時進行資料正規化與驗證。

## 🏗️ 專案架構

Orbit AI 是純靜態架構，`index.html` 只保留畫面標記，樣式與邏輯各自集中在單一檔案：

```text
index.html          — 版面標記（主畫面、編輯器、時間模擬、外觀設定等區塊）

css/
└── styles.css       — 全部樣式（淺色 / 深色模式、響應式設計、編輯器介面、外觀系統、動畫）

js/
└── app.js           — 所有邏輯，依功能分段（各段開頭有 `// ---- 原檔名 ----` 註解方便定位）：
                        資料與正規化、星期／週次計算、外觀系統、主畫面即時更新、
                        編輯器（備份、核心流程、教師／課表編輯）、Gemini AI 辨識、
                        啟動流程、時間模擬狀態機
```

`index.html` 只載入 `css/styles.css` 與 `js/app.js` 這兩個檔案（過去依功能拆成十幾個 `<script>`，每次載入都要多發十幾個 HTTP 請求，且啟動時還會用同步請求重新下載每個檔案來計算版本號，導致首次載入明顯卡頓；合併成單一檔案並把版本號計算改成非同步後大幅縮短了啟動時間）。`js/app.js` 內部依原本的載入順序串接，彼此共用同一個全域作用域（沒有打包工具，也沒有模組系統）；啟動流程（原 `bootstrap.js` 段落）必須排在其他功能模組之後、時間模擬狀態機（原 `testsim-runtime.js` 段落）之前執行，因為它負責讀取設定、建立執行中的課表，並啟動每秒更新一次的主畫面時鐘。

## 🔄 即時狀態計算

Orbit AI 的核心 `update()` 函式會持續重新計算目前狀態。

主要流程包括：

```text
取得目前時間
    ↓
判斷星期
    ↓
判斷週次
    ↓
取得今日課表
    ↓
判斷目前課程
    ↓
判斷下一堂課
    ↓
判斷是否為特殊時段
    ↓
更新倒數計時
    ↓
更新畫面
```

因此主畫面的資訊會隨著時間自動變化。

## 🔐 隱私與安全

### 課表資料

一般課表資料儲存在使用者自己的瀏覽器中。

### AI 課表辨識

使用 Gemini AI 時，所選擇的課表圖片會傳送至 Gemini API。

因此請避免上傳包含不希望傳送至外部 AI 服務之敏感資訊的圖片。

### API Key

Gemini API Key 不應直接寫入原始碼。

專案目前將使用者提供的 Key 儲存在瀏覽器本機儲存空間中。

## ⚠️ 注意事項與限制

* 開啟 `index.html` 時，`css/` 與 `js/` 目錄必須存在於同一層，否則樣式與功能無法載入。
* 課表資料預設儲存在瀏覽器中。
* 清除瀏覽器網站資料可能會導致課表遺失。
* 建議定期使用備份功能保存課表。
* AI 課表辨識並非百分之百準確，匯入前應確認辨識結果。
* Gemini AI 功能需要 API Key 與網路連線。
* AI 辨識效果會受到課表圖片清晰度與格式影響。
* 專案目前沒有後端資料庫。

## 🛠️ 開發

Orbit AI 的程式碼依功能拆分於 `css/` 與 `js/` 目錄（見上方「專案架構」）。

修改樣式請編輯：

```text
css/styles.css
```

修改邏輯請編輯 `js/app.js`，依 `// ---- 原檔名 ----` 註解找到對應區段（例如課表計算在「schedule.js」段、編輯器在「editor-*.js」段、AI 辨識在「gemini-ocr.js」段）。新增程式碼時請留在對應區段內，並注意檔案內的先後順序（後面的區段可以使用前面區段定義的函式與變數）——不要另外新增 `<script>` 標籤，避免又拆回多檔案而讓載入變慢。

整體資料流程可以理解為：

```text
使用者設定
    ↓
資料正規化
    ↓
儲存至 localStorage
    ↓
建立執行中的課表
    ↓
根據目前時間計算狀態
    ↓
更新 UI
```

其中課表編輯器主要負責修改設定資料，而執行中的課表則負責提供主畫面即時運作所需的資料。

## 🎯 設計理念

Orbit AI 主要建立在三個核心概念上。

### 1. 一眼就能看懂

使用者打開頁面後，最重要的資訊應該立即可見：

> **我現在要上什麼？**

> **還剩多久？**

> **在哪裡上？**

> **下一堂是什麼？**

### 2. 安全地修改課表

系統因此提供：

* 修改狀態偵測
* 儲存前確認
* 匯入預覽
* 資料驗證
* 備份與還原

### 3. 簡單且容易攜帶

整個應用程式只由靜態的 HTML、CSS、JavaScript 檔案組成，不需要建置流程。

因此可以很容易地：

* 複製
* 分享
* 備份
* 本機執行
* 放到靜態網站
* 在不同裝置之間轉移
